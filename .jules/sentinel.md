## 2025-03-26 - Path Traversal Vulnerability in SPA Catch-all Route
**Vulnerability:** A Path Traversal vulnerability existed in the fallback static file serving logic (`serve_spa`) inside `backend/app/main.py`. The endpoint used `.startswith()` to verify if the resolved absolute path remained inside the intended `frontend_dist` directory. This string-based prefix check is fundamentally insecure, because if `frontend_dist` is `/app/frontend/dist` and the user requests `../dist_secrets`, the resulting path `/app/frontend/dist_secrets` still starts with `/app/frontend/dist`, thereby bypassing the security check and allowing attackers to read files outside the intended web root.
**Learning:** Never use string methods like `.startswith()` for path boundary validation. It falsely validates adjacent sibling directories sharing the same prefix name.
**Prevention:** Always use `os.path.commonpath([target_path, base_directory]) == base_directory` after resolving both to absolute paths with `os.path.abspath`. Catch `ValueError` to handle cross-drive exceptions properly (e.g. on Windows systems).
