## 2024-05-19 - Path Traversal bypass via `.startswith()`
**Vulnerability:** A path traversal vulnerability existed in the static file serving logic (`backend/app/main.py`). The endpoint `serve_spa` used `safe_path.startswith(frontend_dist)` to verify that a requested file was within the permitted `frontend_dist` directory (`/app/dist`). This is insecure because an attacker could craft a path to access a directory that shares the same prefix, such as `/app/dist-secret`, bypassing the check and reading sensitive files.
**Learning:** Using simple string prefix checking (`startswith`) for file path boundary validation is inherently flawed. It does not respect directory boundaries, leading to path traversal bypasses.
**Prevention:** Always use `os.path.commonpath` on absolute paths (e.g., converted via `os.path.abspath`) rather than string prefix checks to securely prevent path traversal vulnerabilities. Ensure the check catches `ValueError` to handle edge cases where paths reside on different drives (e.g., Windows), falling back to a safe default.
